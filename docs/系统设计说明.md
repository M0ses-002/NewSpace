# 系统设计说明

项目：newspace · Godot 4.x · GDScript · 2D 单机轨道实验室

本说明依据 `res://scripts/kepler_orbit.gd`、`res://scripts/orbit_sandbox.gd` 与 `res://scenes/main.tscn` 编写。文档维护形式为 Markdown 与 Word 同步。自动化测试是否通过，以主对话最终验收为准；本文的性能预算为设计目标，不代表已经实测。

## 1. 目标、边界与实施规划

系统展示静止行星和围绕其运动的飞船，初始轨道为圆。主行星 A 默认位于世界原点；`data/planet_b.json` 存在时，世界在 `(860, 0)` 处增加第二颗与 A 同尺度的行星 B，两者的影响球边界沿 A→B 连线仅相隔 60 km。飞船在任一时刻只归属一个当前焦点天体，解析轨道元素按该天体的局部坐标解释，出球与入球之间按分域轨道（patched conics）交接；详见第 14 节。轨道端点拖拽已取消，四个手柄隐藏且不响应拖拽。ORBIT 模式右侧实际速度滑块以 m/s 调整飞船速率；普通调速固定开始位置与原速度方向，从新状态向量重建安全椭圆，圆速吸附时校正为切向速度并保留绕行方向。引力范围外支持惯性及有限加速目标航行，旧轨迹隐藏；重新入圈后先经过入轨预备和有限推力自动圆化，成功获得安全圆轨道后才显示轨迹。配置与自由规划见第 10 节。

轨道采用理想二体模型：当前焦点天体固定，飞船视作不影响天体的质点。世界上最多存在两颗静态天体，切换焦点只改变局部坐标原点与 μ，速度矢量保持连续。内部 1 世界长度单位 = 1 km，1 时间单位 = 1 模拟秒，位置与半轴使用 km，状态速度与 Δv 使用 km/s，引力参数 μ 使用 km³/s²。界面距离显示 km，速度与 Δv 乘 1000 显示 m/s，周期由模拟秒除以 60 显示 min。屏幕正 y 方向向下，因此当前默认正方向在画面上为顺时针。相机缩放只改变显示，屏幕命中范围、吸附阈值与 UI 布局仍使用屏幕像素。

设定来源：[资料库《千禧年-航空学》](https://www.workbuddy.cn/space/d/6Y3qeJ8TCoKzyiJ8bEkPp4)。行星半径 50 km，表面上方 3 km 为恒强场设定区，场顶/外部开普勒场边界半径为 53 km，g = 9.81 m/s²。在场顶连续匹配 μ = g×(53000 m)² = 2.755629×10¹⁰ m³/s² = 27.55629 km³/s²，场顶圆轨道速度约 721 m/s、周期约 7.7 min。第二颗行星 B 沿用同一组尺度参数，因此两球 μ 相同；两球中心相距 860 km，引力区半径各 400 km，剩余间隙 60 km。场顶外且引力范围内优先采用开普勒解析运动；范围外采用无引力惯性与有限加速度自由航行。回入时先进入无推力数值推进的入轨预备，再进行有限推力自动圆化；数值推进在场顶内将引力强度封顶为配置 g。不实现大气阻力、燃料消耗或完整发动机系统；原型推进受最大加速度与自由最高速约束。

实施按四项连续工作展开：先建立可单独验证的轨道数学模块；再以场景组合实现行星、飞船、端点与线条；随后实现冻结、预览、提交、取消的输入事务；最后由主对话运行自动化不变量与交互验收，并同步两份设计说明。当前范围为桌面 2D 单机验证，已增加卫星、碎片、敌船、雷达与导弹战斗原型；关卡进度写入本地 user:// 文件；不引入多人同步或跨场景全局状态。

## 3. 关键接口与状态契约

数学类 `KeplerOrbit` 继承 RefCounted，全部方法为静态方法，不读取场景节点。轨道字典仅包含 `a: float`、`e: float`、`angle: float`。下列为接口摘要，具体实现以脚本为准。

```gdscript
static func make(a: float, e: float, angle: float) -> Dictionary
static func point_at(orbit: Dictionary, eccentric_anomaly: float) -> Vector2
static func endpoint(orbit: Dictionary, index: int) -> Vector2
static func state_at(orbit: Dictionary, mean_anomaly: float, direction: float = 1.0, mu: float = -1.0) -> Dictionary
static func mean_at(orbit: Dictionary, position: Vector2) -> float
static func velocity_at(orbit: Dictionary, position: Vector2, direction: float = 1.0, mu: float = -1.0) -> Vector2
static func from_state(position: Vector2, velocity: Vector2, circle_angle: float = 0.0, mu: float = -1.0) -> Dictionary
static func speed_interval(position: Vector2, velocity: Vector2, mu: float = -1.0) -> Vector2
static func constrained(position: Vector2, e: float, angle: float) -> Dictionary
static func fit_axis(position: Vector2, target: Vector2, index: int, drag_start: Dictionary, previous: Dictionary, snapped: bool, zoom: float = 1.0) -> Dictionary
static func fit_endpoint(position: Vector2, target: Vector2, index: int, previous: Dictionary) -> Dictionary
static func residual(orbit: Dictionary, position: Vector2) -> float
static func polyline(orbit: Dictionary, segments: int = 320) -> PackedVector2Array
```

`make` 仅打包参数，不承担合法性检查。`constrained` 由锚点与候选 e、angle 推导 a，违反约束返回空字典；`state_at` 返回位置与速度；`residual` 返回椭圆方程绝对残差。`state_at`、`velocity_at`、`from_state` 与 `speed_interval` 增加可选尾参 `mu := -1.0`：缺省或小于 0 时沿用全局 `MU`（由主行星场顶与 g 派生），传入非负值则改用该天体的 μ，因此单行星旧调用与旧测试行为不变。`fit_axis` 与 `fit_endpoint` 保留为数学兼容接口；当前端点拖拽已取消，`begin_drag` 不响应，不能把这些接口视为可用的场景拖拽功能。

场景控制器公开 reset、begin_drag、update_drag、finish_drag 与 toggle_pause，并新增 `begin_speed_drag() -> void`、`change_speed(requested: float) -> void`、`finish_speed_drag(commit: bool) -> void`。ready 中连接按钮 pressed，以及滑块 drag_started、value_changed、drag_ended 信号。数学接口 `from_state` 返回 `{"orbit": Dictionary, "mean_anomaly": float, "direction": float}`，非法或不安全状态返回空字典；`speed_interval` 返回当前位置、固定速度方向下的合法速率上下界 Vector2，不存在合法区间时返回 Vector2.ZERO。上述数学与调速接口的位置、半轴单位均为 km，速度与速率区间单位均为 km/s；change_speed 的 requested 也使用 km/s，m/s 转换只用于界面显示。

多天体相关只读接口为 `body_at(index) -> Dictionary`、`focus_body() -> Dictionary`、`focus_center() -> Vector2`、`focus_mu() -> float`、`focus_field_top() -> float`、`focus_planet_radius() -> float`、`local_position() -> Vector2` 与 `has_second_planet() -> bool`。`bodies` 为静态天体表，每项含 `{name, center, radius_km, field_top_km, gravity_m_s2, mu, gravity_radius_km}`；`focus_index` 取 0（A）或 1（B），`gravity_radius` 始终与当前焦点天体的影响球半径同步。飞船节点位置 `ship.position` 是世界绝对坐标，而 `orbit`、`mean_anomaly`、`anchor` 与轨道预览全部在 `local_position() = ship.position - focus_center()` 的局部坐标中表达；绘制时再加回 `focus_center()`。

控制器 motion_mode 分为 ORBIT、FREE、NUMERICAL、CAPTURE_PREP、CAPTURE_BURN、CAPTURE_FAILED 与 COLLISION；自动入轨使用 capture_remaining、capture_elapsed、capture_direction，orbit_acquired 控制轨迹显隐。FREE 航段 phase 分为 INERTIAL、BRAKE、ACCEL、CRUISE、DECEL、BOUNDARY、ARRIVED。pending_simulation_time 保存未消费的模拟时间。轨道状态包含当前轨道 orbit、预览轨道 preview、平近点角 mean_anomaly、当前速度 velocity；端点拖拽相关变量仅为旧实现残留，不对应可用交互。调速事务另存 speed_dragging、speed_start、speed_bounds、speed_limited 与 speed_cancelled，复用 anchor、old_velocity 和 preview；新增 slider_display_bounds、circular_speed、circular_available 与 speed_snapped，分别表示显示区间、当前位置圆速、圆速可用性与本次吸附状态。speed_ignore_press_value 和 speed_press_position 记录按下意图，防止零拖动改变轨道；orbit_direction 保存绕行方向，用于提交后的状态计算与相位推进。manually_paused、dragging 与 speed_dragging 独立，物理推进条件为三者均为 false；端点拖拽入口不响应。提交或取消后保留先前的手动暂停选择。

## 4. 开普勒几何与时间推进

令 a 为半长轴，e 为偏心率，ω 为轨道主轴方向。u = (cosω, sinω)，v = (-sinω, cosω)。半短轴 b = a√(1-e²)，椭圆中心 C = -aeu。当前焦点天体的中心位于该局部坐标的原点 O = (0,0)，不是一般椭圆的几何中心。

偏近点角为 E 时，位置公式为：

```text
r(E) = a(cosE - e)u + b sinE v
P0 = a(1-e)u               近心端，E = 0
P1 = -aeu + bv            短轴正端，E = π/2
P2 = -a(1+e)u              远心端，E = π
P3 = -aeu - bv            短轴负端，E = 3π/2
```

当 e = 0 时，a = b，中心与焦点重合，椭圆退化为圆。此时主轴方向在物理上不唯一，四端点仅为数学几何参考，不提供当前操作；不把圆错误地解释为有唯一长短轴的普通椭圆。

时间推进采用平近点角 M，而非匀速沿折线移动：平均运动 n = √(μ/a³)，μ 取当前焦点天体的 `focus_mu()`，每个物理步推进 M = wrap(M + orbit_direction×nΔt)。通过开普勒方程 M = E - e sinE，以 Newton 迭代求 E，再解析计算位置与速度。当前 state_at 最多迭代 14 次，修正量小于 10⁻¹² 时提前退出。

```text
dE/dt = n / (1 - e cosE)
v(E) = [-a sinE u + b cosE v] · dE/dt
周期 T = 2π√(a³/μ)          模拟秒；界面显示 T/60 min
比机械能 ε = -μ/(2a)
比角动量绝对值 h = √[μa(1-e²)]
```

初始半径默认 240 km，即距 50 km 表面的高度 190 km，e = 0，初始 M = 0.5，simulation_speed 默认 60，表示 1 现实秒推进 60 模拟秒。两球同尺度，μ = 27.55629 km³/s²。simulation_speed 仅改变模拟时间推进；实际速度滑块内部 API 以 km/s 改变状态速度，界面显示 m/s，由此改变轨道与周期，不修改时间倍率。MIN_PERIAPSIS = 76 km 保留为安全近心半径，对应地表安全高度 26 km、高于场顶 23 km；所有可编辑椭圆的几何近心均高于场顶；实际运动仅在当前焦点天体的引力范围内受反平方引力，超出该影响球转惯性自由飞行，若惯性航迹随后与另一天体的影响球相交则交由其捕获（第 14 节），出圈后轨迹线隐藏。53 km 圆仅为设定参考，不在安全编辑范围。MAX_A = 1000 km、MAX_E = 0.85 保持。初始圆速约 338.85 m/s，周期约 74.17 模拟 min；60 倍时间下约 74.17 现实秒一圈。解析推进避免逐帧数值积分的长期能量漂移；折线只参与显示。

调速状态反解采用 ε = |v|²/2 - μ/r、h = q.x×v.y - q.y×v.x、a = -μ/(2ε)，偏心向量为 (v.y×h/μ-q.x/r, -v.x×h/μ-q.y/r)。仅接受 ε < 0、非零角动量与 e ≤ 0.85、a ≤ 1000 km、a(1-e) ≥ 76 km 的安全椭圆，浮点边界使用代码中的微小容差；e < 10⁻⁶ 时归零并沿用 circle_angle。返回反算相位及角动量方向；场景默认顺时针，提交与后续推进保持原角动量的绕行方向。

合法速率区间由 speed_interval 解析求交。令 β = h²/(r²|v|²)、x = r|v|²/μ、k = 76/r，则 e² = 1-βx(2-x)。偏心率给出 x ∈ [1-s,1+s]，s = √[1-(1-0.85²)/β]；半长轴限制上界 x ≤ 2-r/1000，近心限制通常给出下界 x ≥ 2k(1-k)/(β-k²)。r 接近 76 km 时要求切向方向并令 x ≥ 1；无合法交集返回零区间。换回速率 √(xμ/r) 前向内收浮点级余量；控制器再包含当前合法速率，避免按下即产生微小 Δv。边界取决于当前位置和方向，滑块不能任意推进到逃逸、撞击或过度偏心轨道。

## 5. 历史数学接口：锁轴旋转与圆吸附

本节仅记录历史数学求解和兼容接口，不是当前交互：四端点隐藏，`begin_drag` 直接返回，用户无法拖动轨道；以下“拖拽”“吸附”均指历史行为。当前速度滑块圆速吸附见第 9 节。

开始拖拽时缓存飞船世界位置 q = anchor 与按下时轨道 drag_start，随后停止相位与 elapsed_simulation 推进。历史交互由 fit_axis 求解：常规拖长轴锁定开始时的 b，拖短轴锁定开始时的 a；圆吸附区允许两轴同时微调。行星焦点始终固定，预览始终经过 q，满足以下几何关系与安全约束：

```text
p = |q| + e(u · q)
a = p/(1-e²)
0 ≤ e ≤ 0.85
a(1-e) ≥ 76 km
a ≤ 1000 km，且 a > 0
```

令 r = |q|，a₀、b₀ 为拖拽开始半轴。目标 t = mouse_world + drag_offset；把 t 相对开始端点的位移投影到开始时所选端点的外向轴，得到 d。索引 0、2 请求 a = a₀ + d、b = b₀；索引 1、3 请求 a = a₀、b = b₀ + d。投影基准不会随预览旋转或吸附累计变化，垂直于该轴的鼠标位移不直接改变半轴。未吸附且 previous 与 drag_start 相等时，若 |d| < 0.0001 km，直接返回开始轨道副本，避免未移动就改变轨道。确定合法 a、b 后由 e = √(1-b²/a²) 及 cosν = (b²/a-r)/(re) 求出两个主轴方向，选取相对 previous.angle 旋转较小的一支；e ≤ 10⁻⁸ 时保留原方向。由此自动旋转椭圆以经过冻结船点，所选端点不要求与鼠标重合。

到达物理边界后半轴停止变化。长轴模式将请求 a 截断到下界 max[b,(b²+r²)/(2r)] 与上界 min[1000,b/√(1-0.85²),(b²+76²)/(2×76)]；短轴模式将请求 b 截断到下界 √max[a²(1-0.85²),2a×76-76²] 与上界 min[a,√max(0,2ar-r²)]。这些区间同时保证 a ≥ b、近心点不小于 76 km、e ≤ 0.85、a ≤ 1000 km，以及近心距离 ≤ r ≤ 远心距离；继续向不可行方向拖动时不生成非法轨道。预览仍经归一化椭圆方程断言残差小于 10⁻⁵。

圆吸附以未截断请求半轴计算 s = max(|a请求-r|,|b请求-r|,|a请求-b请求|) × zoom。未吸附时 s ≤ 10 屏幕 px 进入；已吸附时 s ≤ 18 屏幕 px 保持，超过 18 才退出。还要求 76 ≤ r ≤ 1000。吸附结果直接设置 a = b = r、e = 0，保留 previous.angle，允许原本锁住的半轴作小范围修正，得到精确圆而非仅视觉上近圆。继续拖动越过退出阈值后恢复锁定开始时另一半轴的常规模式，因此可离开圆；10/18 px 滞回用于减少边缘抖动，阈值不随相机缩放改变屏幕大小。

fit_endpoint 仅保留为数学兼容接口：它以端点到目标的距离平方为代价，先尝试长轴解析解或短轴一维求根，再使用 24×7 粗种子与前 5 个种子的最多 40 轮局部搜索，必要时保留 previous。该接口在固定焦点、固定锚点下搜索 e 与 ω；相关端点拖拽已取消，这些求解仅供数学兼容使用。

## 6. 输入事务、释放与取消

以下端点操作表和公式为历史拖拽事务记录，当前端点拖拽已取消、不响应；现行交互为 ORBIT 速度滑块、FREE 世界左键设目标与右键或 Esc 取消目标、Space 暂停、R 重置及滚轮缩放。捕获期间速度条只读。

左键按下由 unhandled_input 检测四个端点，命中距离乘相机缩放后不超过 22 屏幕像素。命中后固定 selected_handle，冻结 q 与 old_velocity，分别复制原轨道为 preview 与 drag_start，并初始化 circle_snapped。每次 update_drag 将冻结锚点、含偏移的鼠标目标、所选索引、drag_start、preview、circle_snapped 与 camera.zoom.x 传给 fit_axis，再接收 orbit 与 snapped。拖动更新只修改预览、吸附状态与辅助几何，不改 orbit、飞船位置或旧速度。

左键释放先在 input 中处理，即使鼠标位于 HUD 上方也会结束拖拽。释放先以最终鼠标位置更新预览，再提交：求新轨道在 q 处的切向速度、计算 Δv、复制轨道、由 q 反算 M。提交这一瞬间显式保持 ship.position = anchor；下一物理步才沿新轨道继续运动。

```text
p = a(1-e²)
e_vec = eu
w = e_vec + q/|q|
direction = sign(q.x×v_old.y - q.y×v_old.x)
v_new = direction · √(μ/p) · (-w.y, w.x)
Δv = |v_new - v_old|
```

direction 取 q×v_old 的角动量符号；正向速度对应屏幕顺时针运动，提交保持原绕行方向。提交改变速度向量，不沿新轨道寻找另一位置，因此不造成瞬移。飞船朝向由 velocity.angle() 同步。

| 操作 | 状态与效果 |
|---|---|
| 左键拖动任一端点 | 暂停物理推进，显示旧轨道与新预览、锚点和两条速度示意 |
| 左键释放 | 提交新轨道，保持释放瞬时位置，记录本次 Δv |
| Esc | 拖拽中取消，保留旧轨道、位置、速度与相位 |
| 世界区域右键 | 拖拽中取消；右键当前走 unhandled_input |
| 应用失去焦点 | 若正在拖拽则取消，避免窗口切换留下冻结事务 |
| Space 或暂停按钮 | 若正拖拽先取消，然后切换手动暂停 |
| R 或重置按钮 | 终止规划，恢复初始圆轨道、初始相位、零累计时间与 Δv，缩放归一 |
| 鼠标滚轮 | 非拖拽时按 1.12 倍缩放，范围 0.22 至 2.0 |

取消路径不提交 preview。若操作前已经手动暂停，取消或释放后仍暂停；若此前运行，则恢复运行。调速期间禁用世界滚轮缩放，避免规划期间坐标含义发生变化。

实际速度滑块按下后由 begin_speed_drag 冻结飞船位置、旧速度、相位与累计模拟时间，计算并固定旧方向的合法区间 speed_bounds。change_speed 先以原始请求值判断圆速吸附；普通分支再夹到 speed_bounds，以 old_velocity.normalized() × actual 调用 from_state 重建 preview，失败时保留上次预览并提示夹限。按下拇指但未水平拖动不改变轨道。调速过程中只显示候选轨道及速度，不改变当前 orbit 或船位置。滑块 drag_ended 提交，保持 anchor 不变、应用新速度与完整向量 Δv、重算相位并保存 orbit_direction，再按原手动暂停状态恢复；键盘改变滑块值执行一次即时调速事务。Esc 或失焦取消调速，暂停切换先取消再切换，重置清除事务并恢复初始圆。提交、取消和重置均清理 speed_snapped 与按下保护，取消后屏蔽残余滑块变值。端点拖拽已取消；FREE 模式右键取消自由目标。

圆速标记、切向圆化及输入吸附规则详见第 9 节；该速度条的 8/14 px 滞回独立于第 5 节轴拖拽的 10/18 px 滞回。

## 7. 显示、资源与性能预算

CurrentOrbit 仅在已获得轨道且处于 ORBIT 时显示，出圈及入轨未成功时隐藏；PreviewOrbit 在速度调节事务中显示候选椭圆，Anchor 标记冻结位置。四端点与辅助轴线均隐藏，端点不可拖拽。两条速度线使用独立基础示意比例 VELOCITY_VISUAL_SCALE = 160，共同显示比例为 160/camera.zoom.x，将 km/s 速度向量乘以该比例后加到锚点，线宽同为 2/camera.zoom.x；长度与线宽随相机缩放反向补偿以保持屏幕可读。该补偿不改变物理速度，也不表示真实位移或预测轨迹。HUD 展示 a、b（km）、e、中心距离、当前高度、近远心高度（km，均以 50 km 表面为高度零点）、速度与 Δv（m/s）、周期与已过模拟时间（min）。调速预览期间，速度栏和滑块数值显示候选轨道在冻结点的实际速率，旧速度由白色示意线保留。调速提示区分普通固定方向、圆速吸附校正切向及安全边界夹限。SpeedControl 位于右侧参数栏下方，右锚定，顶部 455 px、底部 690 px、宽 324 px、距右边 26 px；包含标题、m/s 数值、本次调速倍率、HSlider、圆速刻度、圆速与吸附状态 Label、旧方向合法速率范围与操作说明。CircularMarker/Tick/Diamond 与 CircularSpeed 均为场景资源中的编辑器可见节点，不拦截鼠标；标记可用时显示青绿色，已吸附时变橙色，不可用时隐藏并说明范围原因。_slider_x 按主题拇指半宽与有效轨道宽度定位，滑块 resized 时重新定位。SpeedSlider 在 ORBIT 模式支持实际轨道调速，内部连续取值（km/s）且关闭滚轮改值；有焦点时左右键每次改变 0.001 km/s，即 1 m/s，Home/End 到旧方向 speed_bounds 合法端点。FREE 模式它只读实时显示实际速率，显示范围覆盖当前速率与设定上限；所有非 ORBIT 模式，包括预备、燃烧、失败、NUMERICAL 与 COLLISION，均禁用轨道调速。其下 FreeMaxControl 仅 FREE 可见，MaxSpeedSlider 设置自由飞行最高巡航速率，内部 km/s、显示 m/s，步长 0.001 km/s，下限 0.01 km/s，上限由配置默认自由最高速的两倍确定（不低于下限）。修改设定不瞬时改变实际速度；已有未完成目标时从当前状态先制动重规划，若规划失败则恢复原设定与旧计划。倍率为本次候选速率/开始速率，仅用于说明本次改变量。左上 Units 标签另示 1 世界单位 = 1 km、50/3/53 km 设定尺度、场顶 g、当前时间倍率和 26 km 安全高度。

每条轨道默认分 320 段、321 个采样点，仅在重置、规划和缩放等几何刷新时重建；普通物理步更新解析位置与 HUD，不重新采样整条轨道。主轨道线宽按相机缩放作反向补偿；端点虽保留资源但始终隐藏，不提供命中操作。

桌面性能目标为 60 FPS，对应总帧预算约 16.67 ms。该数值是设计预算，不是本轮实测结果。历史 fit_axis 与 fit_endpoint 仅为数学兼容接口，不再承担鼠标拖拽开销。验收应记录实际设备、分辨率、调速预览和数值推进入轨时的帧时间。

当前资源较轻，脚本和可视场景采用 preload 与 PackedScene 实例组合。移动端若成为目标，应另行测量内存与帧时间，优先减少重复采样和拟合事件、复用采样缓冲，再按需采用异步资源加载；不能把桌面 16.67 ms 目标当作移动设备达标证据。

## 9. 速度条圆轨道标记与吸附

当前速度面板标题为“速度”，显示速度、夹限状态、滑条、圆速及吸附状态、合法速度范围；FREE 模式另显示最大速度控件。朝向面板显示偏角、夹限状态、滑条及可行范围。两处默认隐藏操作提示，朝向详细读数节点保留且仍更新但默认隐藏；交互期间的详细操作提示仍由 Feedback 显示。面板精简不改变滑条事务、键盘操作、圆速吸附或互斥规则。两个面板各有独立深色半透明 ColorRect 背景，颜色为 `Color(0.025, 0.055, 0.085, 0.88)`，鼠标过滤为 IGNORE；背景与控件同为 Layout 子节点，保留原控件路径。专项自动化结果由团队提供：速度 16948/0、朝向 96/0。团队曾在加背景前进行 1280×800 实窗截图核验：未见面板控件文字截断重叠，但轨道和雷达线穿过透明速度面板；新增背景后，独立验证者在 1280×800 OpenGL 窗口复核：轨道和自由飞行模式下背景覆盖完整面板并压暗轨道及雷达线，滑条、数值、圆速标记及自由最高速度控件无截断；模拟鼠标注入操作三条滑块均能改变数值。此次视觉与交互复验仅覆盖 1280×800，未验证背景空白处的鼠标透传或其他分辨率。

自由航行由 `scripts/free_flight.gd` 的实例保存 position、velocity、target、requested_target、boundary_crossing、has_target、phase、segments、route 与 entry_body_index，单位为 km、km/s、模拟秒。`set_state(p, v)` 接管实际状态并清旧计划；`plan_bodies(destination, bodies) -> bool` 创建多天体计划，`bodies` 每项为 `{center, radius, entry_limit}`，中心与半径使用世界坐标与 km，`entry_limit` 为入球峰值速度上限（km/s；0 表示不额外限制）；`plan(destination, gravity_radius) -> bool` 保留为单圆包装，等价于以世界原点、该半径和 0 上限调用 `plan_bodies`。`advance(delta) -> float` 推进并在穿界时返回未消费时间，`cancel()` 清目标与航段并保持当前位置和速度进入 INERTIAL。主控制器 `set_free_target(world_position) -> bool` 接受 FREE 模式且飞船位于引力范围外或边界容差内的请求；地图左键选择目标，HUD 区域不触发目标选择。

规划从当前实际位置和速度开始，先以有限最大加速度沿旧速度反向制动至零速；制动时间 t_b=|v|/a，制动终点 p_b=p+v·t_b/2。制动段必须避开每个"飞船在其外"的引力圆：起点已在某圆内时该圆不参与避让与截断，否则制动线一旦穿圈即拒绝计划并保留旧计划。不穿入任何引力圈的普通目标随后沿直线加速、可选匀速、减速到零速：距离 L，峰值速度 v_peak=min(v_max,√(La))；短途为三角速度曲线，长途达到上限后增加匀速段，抵达进入 ARRIVED。真正入圈的航线则从制动终点朝最早入圈点加速、可选巡航，不在边界减速；可达入界速度 v_entry=min(v_max,√(2aL))，短距离时受加速度限制，不能承诺达到设定上限。多圆规划再对峰值加一层 `entry_limit` 约束：穿界航段 `peak = min(max_speed, √(2·d·a), entry_limit)`（未穿界的普通抵达仍只取 √(d·a) 与上限），其中 `entry_limit = 0.9 × √(2μ/R)`，即目标天体在影响球边界处逃逸速度的 0.9 倍，保证入球速度低于逃逸速度、能被捕获而非直接穿过。各段解析计算 p(t)=p₀+v₀t+at²/2、v(t)=v₀+at，可消费跨阶段大步长。最高速约束作用于新直线航段；若接管初速已更高，先有限制动，不瞬时裁速。

制动仍先从当前真实速度有限减速；`segment_clear(a, b, radius, center)` 检查当前位置至制动终点的线段，允许边界接触与浮点容差，但实际穿入任一引力圆仍拒绝并保留旧计划。制动安全后，`first_boundary_target(start, destination, radius, center)` 求沿线首次接触点；多圆规划对每个有效圆分别求交，取航段比例最小者为目标截断点，并记录对应的 `entry_body_index` 供跨球交接使用。结合径向方向判断是否真正入圈。入圈航段以该边界点为交接点，保留 requested_target 与指向点击点的路线显示；纯切线不触发入圈，普通圈外航线按目标抵达。自由目标导航不自动绕路。

真正入圈时 phase 进入 BOUNDARY，继承边界位置与速度，由 `_enter_gravity(remaining, body_index)` 取消自由目标、切换 `focus_index` 与 `gravity_radius`，以连续的真实位置速度进入 CAPTURE_PREP，随后自动有限推力圆化，并将当前步未消费时间交给该模式；引力范围内不继续自由目标导航或施加其发动机推力。重设从当前速度重新制动规划，非有限状态或制动段穿圈等失败保留旧计划；右键或 Esc 取消目标后保持当前速度惯性飞行。自由航行也受手动暂停和模拟时间倍率控制，目标与路线可视尺寸按相机缩放补偿。此前 `tests/free_flight_boundary_target.png` 为旧边界停车版本截图，不代表当前入圈行为。

最终 HUD 提示使用“入轨完成后显示轨道”“轨道已隐藏”和“入轨完成前不显示轨道”，与实际显隐一致。

### 10.1 真实跨界、数值回入与表面碰撞

ORBIT 的 `_advance_orbit` 由椭圆与当前焦点天体引力范围圆的解析交点求出界偏近点角，再换算平近点角与所需模拟时间；是否出球用 `local_position().length()` 判定，先精确推进至该相位，保留边界瞬时位置和速度转 FREE，当前步剩余时间按惯性继续推进。完整椭圆外段不对实际运动继续施加引力。NUMERICAL 向外跨界时也在当前小步内定位边界时刻，保持位置与速度连续，再将余时交给自由推进。上述判定与交点求解均使用局部坐标，因此绕 B 运行时以 B 的 400 km 影响球为准。

FREE 的惯性状态通过 `_entry_time` 检查直线是否严格穿入任一引力圆：该函数遍历 `bodies`，对每颗天体把状态平移到其中心后求最早入球时刻，返回 `{time, index}`（无入球时 time = INF、index = -1）。目标导航触发的真正入圈则由 BOUNDARY 按同一 `_enter_gravity` 分支交接。点积、叉积与判别式按双精度分量计算并使用相对容差，纯切线不回入，远离圆或时间窗口外不触发。到达回入点后取消自由目标，切换焦点天体并继承真实位置和速度进入 CAPTURE_PREP，不直接反解切回 ORBIT。预备持续 5 模拟秒、仅受引力，暂停时倒计时冻结；余时可跨阶段消费。随后 CAPTURE_BURN 每步最多 0.25 模拟秒，以不超过配置最大加速度的推力将速度修正向当前半径的切向圆速 √(μ/r)，保留入界角动量方向。只有 `Orbit.from_state` 有效、偏心率 ≤ 10⁻⁶、半径处于安全近心半径至 min(最大半长轴, 引力半径) 且速度向量距目标圆速 ≤ 5×10⁻⁷ km/s，才建立圆轨道、切回 ORBIT 并显示轨迹。燃烧超过 3600 模拟秒未成功则 CAPTURE_FAILED，继续数值引力推进而不虚报成功；预备或燃烧中逃出引力范围则保留实际位置速度进入 FREE 并提示失败。

NUMERICAL 使用 velocity Verlet 连续积分，小步上限为 0.25 模拟秒，并按半径/速率尺度缩步以处理近中心高速状态。`_gravity(p, body_index)` 的强度为 μ/max(r²,r_top²)，方向指向当前焦点天体（或指定天体）的中心；因此场顶外为反平方，场顶内为恒强封顶 g。每次推进最多 `MAX_NUMERICAL_STEPS = 2048` 步，剩余时间存入 `pending_simulation_time`，预算耗尽后设置 manually_paused=true 安全暂停，不静默丢弃余时；HUD 显示待推进的模拟秒数及“空格继续消化剩余时间”。按空格恢复后继续消费缓存时间，已过模拟时间仅累计实际消费的时间；暂停期间不消费积压时间。

每个数值小步通过 `_surface_contact_time` 沿本步抛物积分轨迹 p(t)=p+vt+at²/2 定位首次表面接触时间：该函数遍历全部天体，先检查接触可能性并定位最小半径时刻，再以 40 次二分定位第一次触及对应天体表面半径的时间，取最早者作为接触点。接触即进入 COLLISION，保留接触点、velocity=0、manually_paused=true，清自由目标与计划；碰撞状态停止后续运动，显示表面碰撞提示，按 R 重置恢复初始圆、时间与事务状态。碰撞未消费的时间不继续推进穿过表面。窗口参考图为 `tests/gravity_range_visual.png`、`tests/free_flight_brake_visual.png`、`tests/free_flight_visual.png`；这些为历史轨道/自由飞行截图，不代表当前战斗界面。

## 11. 轨道朝向轴

### 11.1 玩法语义

朝向轴在保持飞船当前位置 r 与速率大小 |v| 不变的前提下旋转速度方向，因此半长轴 a 与周期不变，只改变偏心率和拱线朝向。速度滑条改变能量对应的 a 与速度大小，是「油门」；朝向轴改变同一能量下的形状与径向分量，是「方向盘」。两者构成正交两轴：一个管能量与切向尺度，另一个管偏心率与拱线朝向。

### 11.2 数学与可行域

记 r 为当前位置半径、a 为当前半长轴、γ 为飞行路径角（速度相对当地切向的偏角），β 与偏心率满足：

```text
β = r / a = 2 − r|v|²/μ
e(γ) = sqrt(1 − β(2 − β)cos²γ)
e(0) = |1 − β|
e_cap = min(MAX_E, 1 − MIN_PERIAPSIS / a)
γ_max = arccos sqrt[(1 − e_cap²) / (β(2 − β))]
Δv = 2|v| sin(|Δγ| / 2)
```

e 关于 γ 为偶函数，并随 |γ| 单调增大，因此可行域关于 0 对称，滑条的左右两侧边界等值。可行域为空的唯一条件是当前位置已使 e(0) 触及上限，即飞船已贴在 76 km 安全近心边界或 0.85 偏心率边界；此时 HUD 显示无旋转余量，滑条禁用。`heading_limit` 在解析边界上内收 1e-5，避免单精度状态向量在精确边界被 `from_state` 拒绝。默认配置下 MAX_E = 0.85、MIN_PERIAPSIS = 76 km。

实现上航迹角由 `Orbit.flight_path_angle(position, velocity, orbit_direction)` 内部按绕行方向构造切向，因此顺行与逆行都返回带符号的正确航迹角；调用方不得再乘 `orbit_direction`。早期实现重复取反会让逆行轨道拖动首帧镜像跳变，现已修复并补充夹具。

### 11.3 玩家交互

HUD 左下 `AngleControl` 提供朝向滑条，`BaseMarker` 标出零偏角。按下冻结模拟并进入预览，拖动只更新预览轨道与新速度方向；松手提交，Esc 取消并恢复原轨道。松开事件在 GUI 分发前处理，指针移出控件也不会留下卡住的拖动状态。提交时位置不跳变，按 `mean_at` 由新轨道重算平近点角；本次调整免费瞬时生效，只把完整速度向量差记录为 `last_delta_v` 供显示，不消耗推进剂或时间。滑条提交时若解析边界仍不可解，则以当前航迹角为基准对偏移量二分 9 次回退；回退终点保持离当前轨道最近，不会退到镜像解，也不保留陈旧预览。

键盘在朝向滑条获得焦点时生效：方向键每次 0.25°，Home/End 直达负/正可行边界。朝向轴与速度滑条双向互斥，一方拖动时另一方禁用；FREE、NUMERICAL、入轨与碰撞等非 ORBIT 模式不支持朝向调整。朝向预览属于 `is_orbit_editing()`，期间战斗推进与导弹冷却冻结，发射被禁用并显示原因，暂停语义与调速预览一致。

### 11.4 敌方转向轴

敌机把加速度预算拆成两个正交通道：切向推力负责能量与半长轴，转向轴只旋转速度方向负责径向速度闭环，原先叠加在切向指令上的径向阻尼项已由转向轴接管。转向角速度上限由剩余法向预算给出：

```text
ω_max = (a_max − |a_tan|) / |v|
```

切向与转向加速度正交合成，总预算不超过配置最大加速度；转向只改方向，因此速率严格守恒、半长轴不被转向改变。转向的偏角上限每步按当前轨道重算，额外封顶远心为 0.9 倍引力半径。相位增益由 15 km/rad、±25 km 调整为 60 km/rad、±45 km，使敌机能在 2000 模拟秒预算内完成对卫星的夺控。

### 11.5 限制

玩家朝向轴只夹 MAX_E 与安全近心，不含远心封顶，因此对大 a 轨道做较大旋转后，远心可能离开引力范围；这是沿用既有轨道编辑边界的已知行为，不是遗漏的守卫。所有朝向轴验收均为 headless 合成输入，未做真实窗口人工鼠标拖动。

## 12. 战斗实体、雷达与敌船显示

`main.tscn` 直接实例化 `combat.tscn`、三颗 `satellite.tscn`、`enemy.tscn`、三块预设 `debris.tscn`、玩家/敌船 `radar.tscn`、三个卫星 `capture_range.tscn` 判定圆和独立 `combat_hud.tscn`；`ship.tscn` 包含 `player_hit_point.tscn`。`scripts/combat.gd` 读取这些既有节点并初始化运行状态，导弹及运行中产生的碎片才动态实例化。卫星场景位置的角度决定初始相位，运行半径取该实例配置；各敌船和预设碎片的初始 Transform 被缓存，重置时恢复并复用，动态导弹和碎片清理。启动加载 `data/combat.json`：玩家、卫星、碎片、雷达、导弹和敌船分别配置生命、碰撞半径、运动、伤害、颜色等；`combat_config.gd` 对必填字段、正有限数、颜色、布尔开关及雷达范围关系整体验证，文件缺失或无效时报告错误并整组使用默认值。配置与轨道的两份 JSON 分开加载。

敌机与卫星场景根节点使用 `entity_host.gd`，可在 Inspector 为每个实例指定 `config_path`；主场景分别使用 `data/enemy_default.json` 和 `data/satellite_default.json`。显式路径优先，路径为空才使用 `combat.json` 对应 enemy/satellite 组作为默认类型数据；显式文件无法读取、JSON 无效、type 未注册或类型数据校验失败时报告错误并禁用该实例，不回退全局数据。卫星 `capture_range_path` 指向对应独立判定圆节点，缺失绑定时该卫星不加入战斗；敌机的 `radar_path` 指向其场景内独立 Radar。各敌机扫描角、锁定及冷却状态独立，但雷达近远半径、扇区角、旋转速率和导弹速度、转向、伤害、寿命、半径及冷却时长仍取全局 `combat.json`，不属于逐实例参数。

实体 JSON 的 `type` 由 `entity_host.gd` 的敌机或卫星注册表分派行为脚本；`orbital_enemy` 与 `orbital_satellite` 从 `data` 读取各自字段，`orbital_enemy_nested` 和 `orbital_satellite_nested` 则分别从 `properties.flight` 和 `properties.orbit` 解析，复用对应基础校验和运动行为。新增类型需实现相应 `parse` / `advance` 契约并注册脚本，不能仅添加任意 type 字符串；当前嵌套类型示例展示不同数据结构，不代表已有不同运动算法。

当前原型初始化三颗环绕卫星、三块碎片与一艘敌船。卫星按配置角速度沿圆轨道运动，玩家或敌船与卫星的相对运动扫掠进入该实例的 `capture_radius_km` 区域时可改变所有权；默认卫星配置的该半径为 90 km，同时控制卫星可视夺控判定圆，独立于玩家 `radar.near_radius_km`；判定圆由 `capture_range.tscn` 的 `Boundary` 绘制，跟随卫星位置并继承其闪烁，卫星没有雷达或扇区；卫星不可被锁定或作为玩家导弹目标；夺控后显示按钮，点击按钮或世界中的己方卫星时，在雷达可见且未暂停或调整的条件下仅发出 `satellite_pressed` 信号，不维修也不清除导弹冷却。敌船选择最近非敌方卫星为目标；在行星表面外且引力区内的初始位置以当地引力对应的切向圆速初始化。运动在引力区内采用与玩家相同的引力模型，区外无引力；有目标时根据目标相位确定参考轨道，以比轨道能量误差控制受限切向推力，径向速度由独立转向轴闭环（见第 11 节），区外有推力时并非纯惯性；无目标时无推力滑行。接触行星表面即从活动敌船中移除，重置恢复初始场景状态。该闭环为原型近似，只能对已验证情形作结论，不保证所有初态稳定夺控或全局安全。敌船仍以独立旋转扇区锁定玩家并跟踪，冷却结束时自动发射。

飞船雷达使用近距离全向圆和远距离旋转扇区：默认近半径 90 km、远半径 250 km、扇区 32°、角速度 0.08 rad/s。近圆用于探测和显示，自动锁定需目标进入扇区；雷达判定不考虑行星、卫星或碎片遮挡。玩家飞船显示近圆和旋转扇区边界；敌船独立扫描，但其雷达指示器隐藏。卫星仅显示圆形夺控判定范围，不显示雷达扇区。

不存在全局战争迷雾：卫星、碎片和导弹保持可见。`radar.restrict_enemy_visibility` 在 JSON 设置初始值，HUD 开关可即时修改当前会话：开启时敌船在玩家近圆或扇区内显示，关闭时始终显示；该开关不改变自动锁定的范围判定，HUD 操作不会自动写回配置文件。无锁定时玩家旋转扇区扫描敌船并选中扫过范围内最近目标；锁定后扇区跟踪目标，目标失效或超出远半径后解除锁定并恢复扫描。

战斗 HUD 的 `Weapons` 位于屏幕底部正中央，包含导弹冷却读数与发射按钮；生命、锁定目标、卫星状态及敌船显示开关仍位于左侧状态面板。玩家无需点击目标即可自动锁定，锁定后通过 HUD 按钮手动发射；点击雷达可见且位于扇区的敌船也可切换锁定；卫星交互不改变锁定。未命中时 FREE 世界左键仍可设置航行目标。玩家和每艘敌机仅在成功发射后启动各自独立冷却，时长由 `missile.cooldown_real_s` 配置，默认且最低为 5 现实秒；玩家 HUD 和敌机血量标签以现实秒显示各自余量。冷却按物理帧真实 delta 推进，与 `simulation_speed` 无关；启动后的首个物理帧不递减，实际可能多一帧。暂停及调速或轨道预览时战斗和冷却冻结，不切换锁定或触发卫星信号，发射按钮禁用并显示原因；恢复后继续，重置时双方冷却清零。旧配置若只有 `missile.cooldown_s`，加载时迁移为默认 5 现实秒，而非按旧值换算。导弹以配置速度推进并限制转向角速度，寿命结束或目标失效时移除。命中飞船（玩家或敌船）只结算伤害，不再生成碎片；导弹扫掠段与卫星圆形结构（卫星半径加导弹半径）相交时，优先在卫星处爆炸，导弹消失并生成一块圆形碎片，卫星本身不掉血、不变更归属，保持卫星只有夺控一个功能。因此当前碎片来源只有导弹命中卫星这一条，调试接口 `spawn_debris` 仍可手动生成。判定使用相对位移短弦扫掠，与玩家撞碎片同一套近似，极端擦边不保证严格连续；卫星判定先于目标判定，被遮挡的目标不会先受伤。导弹追踪为运动学近似，不模拟燃料、弹道或遮挡拦截。玩家使用独立判定点半径与碎片多边形扫掠碰撞，按对象冷却重复扣血；生命耗尽显示死亡界面、暂停模拟，重开按钮重新加载场景。R 重置则重建战斗和轨道状态。

战斗推进采用模拟时间，主控制器按 `combat.max_step()` 限制小步；暂停或轨道调速预览期间不推进。初始碎片及运行中生成的碎片均以自身初始半径绕中心圆周运动，角速度为 `sqrt(mu / r³) * debris.orbit_speed_factor`（默认系数 1）；半径不大于 10⁻⁶ km 时不动。碎片与玩家的碰撞以每个小步的相对短弦近似扫掠，不是精确连续圆弧碰撞。卫星运动及敌船轨道控制同样为原型近似，不能据此推断所有初态都可稳定夺控。扇区自动锁定按子步末位置判定：极高速目标若在单子步内穿过扇区但末点已在扇外，可能漏锁。验收关注配置回退、无视遮挡的范围探测与自动锁定、显隐开关、所有权、受伤、导弹、卫星命中与碎片来源、暂停与死亡重开。本轮 COMBAT_TESTS 170/0；长期 3 相位各 2000 模拟秒的半径区间为 145.0–233.3 / 145.0–225.6 / 225.6–235.0 km，捕获 1/2/1。实际结果以主对话最终记录为准。

## 14. 双天体分域轨道（patched conics）

世界最多包含两颗静止行星：A 位于 `(0, 0)`，B 位于 `(860, 0)`；两者半径均为 50 km、恒强场厚度 3 km、场顶 53 km、g = 9.81 m/s²、引力区半径 400 km，派生 μ 同为 27.55629 km³/s²。两个 400 km 影响球的边界间隙为 60 km（行星表面之间相距 760 km），因此两球之间存在一段明确的无引力通道。控制器在 `_build_bodies()` 中把 `Config.planet` 转为 0 号天体，`Config.planet_b` 非空时追加 1 号天体；`planet_b` 为空则世界保持单行星，所有旧行为不变。

### 14.1 坐标约定

飞船的 `ship.position` 是世界绝对坐标，但解析轨道仍按二体问题求解，因此 `orbit`（a、e、angle）、`mean_anomaly`、`anchor`、预览轨道以及 `state_at` / `velocity_at` / `from_state` / `speed_interval` 的全部输入输出都在"当前焦点天体局部坐标"中表达，即 `local_position() = ship.position - focus_center()`。推进时先以 `focus_mu()` 求平均运动并更新相位，再由 `_refresh_ship()` 把解析结果加回 `focus_center()` 写回世界坐标。绘制轨道线、引力圈、端点手柄与速度矢量时同样加回同一偏移，因此绕 B 运行时轨道线整体平移 860 km 而不改变几何形状；实测绕 B 轨道 321 点质心为 `(860.75, 0)`，每点到 B 中心恒为 240.00 km。

### 14.2 焦点切换与出入球时序

`focus_index` 只取 0（A）或 1（B），`gravity_radius` 始终与该天体的 `gravity_radius_km` 同步。出球在 `_advance_orbit` 内判定：若 `local_position().length()` 已越过当前影响球，或解析椭圆远心超出影响球且相位到达交点，则精确推进到出球时刻，转 `motion_mode = "FREE"`、清 `orbit_acquired`，并以 `flight.set_state(ship.position, velocity)` 保留出球瞬间的速度继续惯性飞行。入球由 `_entry_time(p, v, limit)` 遍历全部天体求得：对每个天体把状态平移到其中心后解直线与影响球的交点，返回最早的 `{time, index}`；`_advance_free` 在剩余时间内推进到该时刻后调用 `_enter_gravity(remaining, index)`。`_enter_gravity` 先切换 `focus_index` 与 `gravity_radius`，再进入 CAPTURE_PREP（5 模拟秒无推力引力飞行）→ CAPTURE_BURN（有限推力圆化）→ 解析圆轨道，因此入球者不会被错误地当作绕 A 运动。

两天体静止且切换焦点只更换坐标原点与 μ，速度矢量原样保留，不施加任何冲量。出球一步与入球一步的速度改变仅为坐标变换带来的浮点误差：本轮实测出球步 3.8×10⁻⁶ km/s、入球步 2.88×10⁻⁵ km/s，二者都远小于 mm/s 量级，不构成可见的轨迹折角。数值推进（NUMERICAL、CAPTURE_*）与表面碰撞检测同样以 `focus_center()` 或各自天体中心为参照，`_surface_contact_time` 与 `_entry_time` 都会遍历 `bodies`，避免飞船穿透另一颗行星表面或漏判入球。

### 14.3 planet_b.json 字段

`planet_b.json` 与 `planet.json` 使用同一套数值校验，额外要求中心坐标；字段缺失、类型错误或校验失败时整组置空，世界退回单行星。

| 字段 | 含义 | 当前值 |
|---|---|---|
| radius_km | 行星表面半径 | 50 km |
| field_thickness_km | 恒强场厚度 | 3 km |
| gravity_m_s2 | 场顶重力加速度 | 9.81 m/s² |
| gravity_radius_km | 影响球半径 | 400 km |
| min_periapsis_km | 安全近心半径 | 76 km |
| max_semi_major_axis_km | 最大半长轴 | 1000 km |
| max_eccentricity | 最大偏心率 | 0.85 |
| center_x_km | 世界坐标 X | 860 km |
| center_y_km | 世界坐标 Y | 0 km |

`Config.planet_b` 为空字典即表示无第二天体；`Config.load_second_planet()` 在文件缺失时静默返回 false，不报错，因此删除该文件即可回到单行星实验环境。`planet.gd` 的 `body_index` 决定实例读取哪一组参数：0 读 `planet`，1 读 `planet_b` 并在缺失时 `visible = false`。

### 14.4 自由飞行多圆避让

`free_flight.plan_bodies(destination, bodies)` 接收全部天体，`bodies` 每项为 `{center, radius, entry_limit}`。制动段必须避开所有"飞船在其外"的圆，起点已位于某圆内时该圆不参与避让与目标截断；目标按所有有效圆中最早的入球点截断，并把对应天体下标写入 `entry_body_index`。峰值速度除受最大巡航速度与加速度限制外，还受 `entry_limit = 0.9 × √(2μ/R)` 约束，即目标天体影响球边界处逃逸速度的 0.9 倍，确保入球速度低于逃逸速度、能被捕获圆化而不是直接穿过。`orbit_sandbox._plan_flight` 为每个天体按上式生成 `entry_limit` 后调用 `plan_bodies`；`plan(destination, gravity_radius)` 仍作为单圆包装保留，行为与旧版一致。

### 14.5 第五关与 orbit_body 胜利

第五关 `data/level_5.json` 的胜利类型为 `orbit_body`，`body_index = 1`。`level_controller._physics_process` 在非暂停、非轨道编辑状态下检查 `sandbox.motion_mode == "ORBIT" and sandbox.orbit_acquired and sandbox.focus_index == 1`，三者同时成立才判胜，因此仅仅穿过 B 的影响球或在自由飞行中路过不算通关，必须完成自动圆化并获得圆轨道。该关无卫星、无敌机、无初始碎片，敌方开火与卫星防御均关闭；四页教程依次为双行星总览、提高速度使远心越过 400 km 出球、出球后惯性直线穿越 60 km 间隙、进入 B 自动捕获圆化。教程不再提及端点拖拽，改为提示拉动速度滑条。

第五关通关后 `level_controller._win()` 不再设置 `get_tree().paused = true`，游戏继续运行，顶部中央仅保留“返回主菜单”按钮；第四关不再是最后一关，其胜利后会显示“下一关”。`_fail()` 仍然暂停场景树并显示失败界面。双天体与第五关的新增回归由主对话执行：`test_two_bodies` 153 条、`test_level_dual` 45 条，均 0 失败；本文不重复其他套件的通过数，实际以主控最终记录为准。
